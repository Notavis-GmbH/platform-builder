## What is LSF Edge Sharpness?

**LSF** stands for **Line Spread Function**. In image analysis, the LSF describes how a sharp edge (like a black-to-white transition) appears in a digital image after being blurred by the imaging system. The **edge sharpness** quantifies how quickly the intensity changes from dark to light across this edge.

A sharper edge means the transition from dark to light happens over fewer pixels. A blurry edge means the transition is gradual and spread over more pixels.

---

## How is LSF Edge Sharpness Calculated?

1. **Sample the Intensity Profile:**
   - We sample pixel values along a circle (ring) at a certain radius from the center of the Siemens star.
   - This gives us a 1D array of intensity values as we move around the edge.

2. **Find the Edge Transition:**
   - We look for places where the intensity changes from dark (low value) to light (high value) or vice versa.
   - For each transition, we measure the distance (in pixels) between the points where the intensity crosses 10% and 90% of the full range between dark and light plateaus.

3. **Calculate Edge Width:**
   - The **edge width** is the number of pixels between the 10% and 90% intensity points.
   - A smaller edge width means a sharper edge.

4. **Compute the Sharpness Metric:**
   - The sharpness metric is calculated as:
     $\text{Sharpness} = 10 \cdot \log_2\left(\frac{\text{Reference Edge Width}}{\text{Measured Edge Width}}\right)$
   - A positive value means the edge is sharper than the reference; a negative value means it is blurrier.

## Visual Example: Edge Profile

Below is a simple drawing of an edge profile and how the 10% and 90% points are used:

```
Intensity
   ^
   |                 ***************  (Light plateau)
   |                *
   |               *
   |              *
   |             *
   |            *
   |           *
   |          *
   |         *
   | ********
   +------------------------------> Position (pixels)
                ^     ^
                |     |
        10% point  90% point
```

- The **distance** between the 10% and 90% points (horizontal axis) is the **edge width**.
- The **steeper** the slope, the **sharper** the edge.

## Diagram: LSF Edge Width vs Radius

The analysis is performed at multiple radii from the center of the Siemens star. For each radius, the LSF edge width is measured as described above. The results are visualized in a diagram:

**LSF Edge Width (10%-90%) vs Radius**

- **X-axis:** Radius (distance from the center of the Siemens star)
- **Y-axis:** Mean LSF edge width for edges on ring (distance in pixels between the 10% and 90% intensity points)
- **Curve:** Shows how the edge sharpness changes as you move from the center outward.

**How to interpret the diagram:**

- A **lower curve** (smaller edge width) means sharper edges at that radius.
- A **higher curve** (larger edge width) means blurrier edges at that radius.
- The diagram helps identify at which radii the image is sharpest or most blurred.

This plot is generated by the software and appears in the top right of the sharpness visualization. Each point corresponds to the measured edge width at a specific radius, and the curve connects these points to show the trend across the Siemens star.

## Parameters (Analyzer Controls)

The software exposes several controls that affect detection, analysis and visualization. Below are the main parameters available from the UI/config and what they do:

- **`rolling_average_window`**: (integer, >= 0)
   - Purpose: Number of frames/images to use for a rolling mean of sharpness and quality values. `0` disables rolling averaging.
   - Effect: When > 0 the analyzer keeps a circular buffer of the best-detected result per frame and plots/uses the mean quality/sharpness over the last `n` frames. Useful to reduce frame-to-frame noise.
   - Recommended: 5 depending on how much temporal smoothing you want; larger values increase latency in reflecting real changes.

- **`threshold_good`**: (double)
   - Purpose: Threshold that decides whether a detection is considered "good" for visualization (green) vs "poor" (red). This threshold is used when coloring position crosses and for part of the UI scale bar logic.
   - Effect: Increasing the threshold makes it harder for a result to be colored green; lowering it shows more green results.
   - Recommended: Set according to your quality metric scale and desired sensitivity. Typical values depend on how your metric ranges are normalized in your setup.

- **`reference_edge_width`**: (double, pixels)
   - Purpose: Reference edge width (in pixels) used to convert measured 10%–90% edge widths to the sharpness metric (logarithmic score). The formula uses this value as the reference for comparing measured widths.
   - Effect: Larger reference width makes the same measured width appear relatively sharper; smaller reference width does the opposite.
   - Recommended: Choose a reference that represents a moderately sharp edge for your imaging setup (e.g., 3–8 px). Tune if the sharpness metric seems biased.

- **`template_match_threshold`**: (double)
   - Purpose: Threshold for the template-matching step used in position detection (how confident the match must be to consider a detection valid).
   - Effect: Higher values reduce false positives but may miss weaker matches; lower values detect more candidates but risks false positives.
   - Recommended: Start with the default used by the app and increase if you observe spurious detections.

These controls are exposed in the service UI and can be changed at runtime; changes typically take effect immediately for subsequent frames.


## Why is this important?

- **Sharp edges** are crucial for accurate measurements and high-quality imaging.
- The LSF edge sharpness metric provides an objective, quantitative way to compare the sharpness of different images or imaging systems.

---

**Summary:**  
LSF edge sharpness measures how quickly an edge transitions from dark to light. It is calculated by finding the width (in pixels) between the 10% and 90% intensity points on the edge profile. A smaller width means a sharper edge.

# MIPI Tricks
## Single Trigger
Single trigger is used for triggering the sensor by software. 
An impulse is handled by the VC FPGA on the MIPI module. 
To enable stop the camera first. Switch to Trigger Mode 4 and restart the camera
Afterwards the button "Single trigger" has a function. 
Be aware, not all sensors have this mode.

For other modes, see [Trigger Mode](https://github.com/VC-MIPI-modules/vc_mipi_raspi/blob/main/docs/trigger_mode.md)
